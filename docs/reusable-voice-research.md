# 재사용 가능한 로컬 목소리 품질 연구

조사일: 2026-09-20. 대상 환경은 Apple M1 16 GiB, MLX Audio 0.5.4와 현재 고정된 Qwen3-TTS 1.7B Base 4-bit입니다. 이 문서는 공식 논문·소스·모델 카드와 [기존 품질 개선 기록](quality-improvement-notes.ko.md)을 연결한 **설계 권고와 실험 계획**입니다. 여기서 제안한 대안 모델이나 평가 모델을 새로 설치하거나 실행한 결과는 아닙니다.

## 먼저 보존해야 할 결과

기존 확인 요청 샘플에 사용한 참조는 48 kHz 원본 PCM의 `[386357:532851]`, 3.051958초이며 SHA-256은 `22133aea2c959269cd804edfdd9bcb1b29945d80b9002782aecfcb15f25d898f`입니다. 전사는 “오늘 재밌는 시간 함께 보내봅시다”입니다. 자동 분석이 찾았던 3.000초 후보는 경계와 바이트가 다르고, 별도 생성 작업도 세 번 만에 실패했습니다. 그러므로 그 3초 후보에 같은 이름을 붙이는 것으로 좋은 참조가 재사용되지는 않습니다. [기존 실험과 공개 샘플 출처](quality-improvement-notes.ko.md#7-공개-샘플의-선택과-한계), [provenance.json](../assets/samples/provenance.json).

우선순위는 **정확히 검증한 참조를 불변 프로필로 등록하고, 다른 화자도 동일한 후보 비교·검토·저장 절차를 거치게 하는 것**입니다. 3.052초라는 숫자나 특정 시드를 모든 사람에게 적용하는 방식은 일반화 근거가 없습니다.

## 1. 공식 자료가 뒷받침하는 범위

Qwen Base의 기본 복제 경로는 참조 음성과 그 전사문을 함께 받습니다. 공식 PyTorch API는 참조 특징을 한 번 계산한 `voice_clone_prompt`의 재사용도 지원합니다. 전사를 생략하는 speaker embedding 전용 모드는 별도로 존재하지만, 제작자는 복제 품질이 낮아질 수 있다고 설명합니다. 이는 이 프로젝트에서 정확한 음성·전사·출처를 저장하는 방향의 근거이며, PyTorch API가 그대로 MLX에 있다는 뜻은 아닙니다. [Qwen 공식 사용법](https://github.com/QwenLM/Qwen3-TTS/blob/022e286b98fbec7e1e916cb940cdf532cd9f488e/README.md#voice-clone).

기술 보고서의 3초 복제 설명은 짧은 입력으로 가능한 기능을 뜻합니다. 모든 화자에게 정확히 3초가 최적이라는 비교 결과는 제시하지 않습니다. 보고서도 내용 일치, 화자 유사성, 여러 언어와 사용 조건을 나누어 평가합니다. 따라서 이 프로젝트의 3–15초 후보 범위는 운영 정책이며, 논문에서 입증된 최적 길이로 표현하면 안 됩니다. 한국어를 포함한 원본 모델의 평가를 이곳의 4-bit 변환·짧은 알림·M1 실행 결과로 바로 옮길 수도 없습니다. [Qwen3-TTS 기술 보고서](https://arxiv.org/html/2601.15621v1).

## 2. 현재 MLX 버전에서 실제로 통하는 제어

MLX Audio 0.5.4의 태그는 `407eb61aec4999ba0c91298095ce7f2ac8c25680`입니다. 아래 내용은 일반 CLI 설명보다 실제 Base 분기와 ICL 구현을 우선해 확인했습니다. [릴리스](https://github.com/Blaizzy/mlx-audio/releases/tag/v0.5.4), [고정된 구현](https://github.com/Blaizzy/mlx-audio/blob/407eb61aec4999ba0c91298095ce7f2ac8c25680/mlx_audio/tts/models/qwen3_tts/qwen3_tts.py#L1126-L1260).

| 항목 | 확인한 동작 | 구현에 반영할 점 |
| --- | --- | --- |
| temperature / top-p / top-k | 기본값 0.9 / 1.0 / 50이 ICL로 전달됨 | 요청값과 실제 적용값을 함께 기록 |
| repetition penalty | Base ICL 진입 시 최솟값 1.5 적용 | 1.05를 설정했다고 1.05 실험으로 기록하지 않음 |
| max_tokens | ICL 생성 루프의 상한 | 토큰 소진을 정상 종료로 간주하지 않음 |
| stream | 별도 디코딩 경로 선택 | 비교에서는 현재 비스트리밍 경로를 고정 |
| speed / Base instruct | 속도는 직접 지원하지 않으며 Base 복제 분기에 스타일 지시를 전달하지 않음 | 사용자가 요청한 속도·감정을 적용했다고 보고하지 않음 |
| seed= 등 임의 kwargs | 이 Base 분기에서 난수 제어로 전달하지 않음 | 백엔드가 MLX 난수 생성기를 명시적으로 설정해야 함 |

시드는 `mx.random.seed()`로 전역 난수 생성기에 지정합니다. 권고 구현은 모델 로드 후 **각 문장·각 시도 직전**에 결정된 시드를 설정하고, 시도 기록에 저장하는 것입니다. 격리된 작업 프로세스에서 처리하면 전역 난수 상태의 동시 변경도 피할 수 있습니다. 시도 번호별로 시드는 달라야 하고, 중단한 같은 시도의 재현에는 같은 시드를 사용해야 합니다. 서로 다른 기기·MLX 버전·배치 방식까지 같은 바이트를 보장한다고 안내하지는 않습니다. [MLX 난수 API](https://ml-explore.github.io/mlx/build/html/python/_autosummary/mlx.core.random.seed.html).

현재 ICL은 참조 코드와 전사 토큰을 메모리에 캐시하고, 참조 코드를 출력 코드 앞에 붙여 디코딩한 뒤 참조 몫을 제거합니다. 따라서 참조의 마지막 소리와 경계는 분석용 장식이 아니라 실제 합성 입력입니다. 내부 캐시는 크기·합계 기반 지문을 사용하므로, 영속 프로필의 동일성은 별도의 SHA-256으로 확인하는 편이 적절합니다. [참조 입력·캐시](https://github.com/Blaizzy/mlx-audio/blob/407eb61aec4999ba0c91298095ce7f2ac8c25680/mlx_audio/tts/models/qwen3_tts/qwen3_tts.py#L606-L803), [참조를 포함한 디코딩](https://github.com/Blaizzy/mlx-audio/blob/407eb61aec4999ba0c91298095ce7f2ac8c25680/mlx_audio/tts/models/qwen3_tts/qwen3_tts.py#L2454-L2518).

## 3. 다른 화자를 위한 참조 선정 원칙

다음은 기존 실패 사례와 위 입력 구조로부터 도출한 설계 권고입니다. 보편적인 자연스러움 판정기로 검증되었다는 뜻은 아닙니다.

1. **실제 발화를 기준으로 후보를 구성합니다.** 하나의 완결된 문장 또는 자연스럽게 이어진 짧은 발화가 우선이며, 가장 짧은 구간을 무조건 우승시키지 않습니다. 기존 원본 후보도 남깁니다.
2. **경계와 전사를 함께 검증합니다.** 타임스탬프 주변 실제 쉼을 확인하고, 원본 샘플 인덱스로 자른 뒤 잘린 파일을 다시 전사합니다. 같은 Whisper로 재전사하는 것은 별도 입력에 대한 확인이지, 다른 모델에 의한 독립 검증은 아닙니다. 반복되는 ASR 오류가 남을 수 있습니다.
3. **전사문을 예쁘게 고치지 않습니다.** 참조에서 실제로 발음한 내용과 맞아야 합니다. 모호한 고유명사·감탄사·겹말이 핵심 구간에 있으면 다른 후보를 우선하거나 짧게 확인합니다.
4. **화자가 불분명하면 중단 지점을 드러냅니다.** 한 YouTube 링크에도 진행자·게스트·삽입 음성이 섞일 수 있습니다. VAD와 ASR 신뢰도는 화자 확인 기능이 아닙니다. 후보 전사·시간·재생 파일을 보여 주고 대상 화자를 확인할 수 있게 합니다.
5. **원본 PCM을 기준으로 보존합니다.** 분석용 리샘플링 파일을 합성 참조로 덮어쓰지 않습니다. 정확한 채널·샘플레이트·샘플 범위·해시를 보존합니다. 일반적인 고주파 삭제나 선행 무음 삭제를 한국어 자음의 잡음 제거로 취급하지 않습니다.
6. **음색과 배경을 구분해 평가합니다.** 배경음·반향·강한 감정·웃음이 섞인 참조와 담백한 참조를 별도 후보로 둡니다. 소음 억제를 도입하더라도 원본과 처리본의 생성 결과를 비교해야 하며, 처리된 참조가 깨끗하게 들린다는 이유만으로 복제 품질까지 좋아졌다고 보지 않습니다.

특히 기존 Karina 참조의 영점 교차 경계가 한 실험에서 좋았다는 사실만으로 모든 후보를 같은 경계나 길이에 맞추지 않습니다. 발화 보존을 우선하고, 경계의 세밀한 조정은 재전사와 제한된 생성 비교를 통과한 경우에만 선택합니다.

## 4. 스킬에서 재사용할 단위

재사용 프로필은 단순한 이름이나 시드가 아니라 다음 기록을 연결해야 합니다. 이는 구현 제안입니다.

| 저장 정보 | 목적 |
| --- | --- |
| 원본 URL 또는 로컬 출처, 부모 파일 해시, 채널·샘플레이트·샘플 범위 | 정확한 참조를 다시 확인 |
| 저장한 참조 WAV와 SHA-256, 정확한 전사와 언어 | 다음 요청에서 같은 입력 사용 |
| 모델·토크나이저 리비전, 백엔드·준비 정책 버전 | 환경 변경으로 인한 품질 변화를 추적 |
| 실제 샘플링 설정, 시도별 시드 정책 | 효과 없는 설정과 숨은 기본값을 구분 |
| 비교에 사용한 문장, 생성 WAV 해시, 자동 검사 결과, 실패 횟수 | 좋은 결과 한 개만 남기는 선택 편향 방지 |
| 사용자의 참조 선택·미리 듣기 검토와 그 대상 해시 | 다른 파일의 승인을 잘못 재사용하지 않음 |

권장 대화 흐름은 `영상 분석 → 후보 2–3개 → 짧은 미리 듣기 비교 → 선택한 참조·조건 저장 → 새 메시지 생성`입니다. 저장 프로필을 선택하면 다운로드·분석·후보 실험을 반복하지 않고 그 참조로 생성합니다. 새 버전의 분석을 실행해도 기존 프로필을 몰래 바꾸지 않습니다.

참조의 검토 상태와 새 출력의 검토 상태는 분리해야 합니다. 좋은 프로필도 새로운 문장에서는 끝말·숫자·발음에 실패할 수 있습니다. 반대로 특정 출력 하나를 거절했다고 참조 자체가 자동 폐기되는 것도 부적절합니다. 기존 `reject → resume` 예산을 유지하면서 참조를 바꾸는 새 비교 작업에는 별도 총예산과 이유를 기록하는 것이 좋습니다.

## 5. 지표별로 말할 수 있는 것

| 검사 | 판단에 도움 되는 내용 | 대신 판단할 수 없는 내용 |
| --- | --- | --- |
| 디코딩·유한 값·길이·클리핑·토큰 종료 | 파일 오류와 명백한 합성 실패 | 자연스러움·인물 유사성 |
| ASR CER와 끝 문구 | 누락·반복·내용 불일치 | 자음의 잡음 여부·유창함·끝 모음 완결성 |
| 끝 에너지 감쇠 | 현재 한국어 끝말 사례의 잘림 위험 | 모든 언어·발성 방식에 대한 정답 |
| DNSMOS SIG / BAK / OVRL | 음성·배경·전체 품질에 관한 보조 비교 | 정확한 한국어 발음·화자 정체성 |
| 화자 임베딩의 코사인 유사도 | 같은 평가 조건의 상대적인 음색 일관성 | 실제 인물 신원·자연스러움·전사 정확성 |
| 청취 A/B | 발음·리듬·잔여 소음·참조와 닮은 정도 | 재현 설정과 출처의 무결성 |

DNSMOS P.835는 원래 소음 억제 평가를 위한 지표이며 음성·배경·종합 점수를 구분합니다. 공식 로컬 코드는 16 kHz, 9.01초 창을 쓰고 짧은 입력을 반복합니다. 따라서 2–4초 알림에서 길이나 마지막 쉼이 달라지면 점수 비교도 영향을 받을 수 있습니다. 같은 참조·문장·시드의 짝 비교에 보조값으로 기록하고, 자연스러움을 대신하는 단일 합격선으로 사용하지 않는 것이 좋습니다. [DNSMOS 논문](https://arxiv.org/abs/2110.01763), [고정된 평가 코드](https://github.com/microsoft/DNS-Challenge/blob/591184a9fcb2cbdec02520fed81a32bbbf9d73ff/DNSMOS/dnsmos_local.py).

독립적인 화자 유사도 연구 후보로 SpeechBrain ECAPA-TDNN이 있습니다. 공개 가중치는 VoxCeleb 1+2로 학습되었고 16 kHz 단일 채널을 사용합니다. 모델 카드는 다른 데이터셋의 성능을 보장하지 않습니다. 한국어 3초 클립에 일반적인 임계값을 그대로 적용하기보다, 같은 화자의 서로 다른 실제 발화끼리 얻은 점수와 다른 화자 점수를 함께 확인해야 합니다. 생성에 사용한 참조 외의 두 번째 실제 발화가 있으면 그 발화에도 유사도를 측정하는 것이 좋습니다. 모델이 이미 사용하는 내부 speaker embedding을 유일한 심판으로 쓰는 방식보다 검증이 분리됩니다. [고정된 ECAPA 모델 카드](https://huggingface.co/speechbrain/spkrec-ecapa-voxceleb/blob/0f99f2d0ebe89ac095bcc5903c4dd8f72b367286/README.md).

NISQA도 일반 전송 음성용 가중치와 합성 자연스러움용 `NISQA-TTS` 가중치가 다릅니다. 코드의 MIT와 달리 공개 모델 가중치는 CC BY-NC-SA 4.0이므로, 단순히 MIT 프로젝트의 기본 의존성으로 추가하는 선택은 피하고 별도 연구 도구로 검토하는 편이 적절합니다. 한국어 짧은 알림의 자동 자연스러움 보증은 확인하지 못했습니다. [용도·라이선스를 명시한 공식 문서](https://github.com/gabrielmittag/NISQA/blob/fe84f0f252abec382b24367d5b22498a7ce34dbb/README.md#paper-and-license).

| --- | --- | --- |
| 완결된 참조와 정확한 전사가 첫 후보 고정 선택보다 안정적임 | 같은 원본에서 참조 후보만 변경 | 새 문장·다른 화자에서 개선이 없거나 실패율 증가 |
| 발화 경계 보존이 임의 길이 맞춤보다 나음 | 같은 전사의 경계만 변경 | 경계 조정이 자음·말끝을 자르거나 재전사 실패 |
| 미리 듣기 결과를 반영한 프로필이 새 문장에도 유효함 | 프로필 선정 방법만 변경 | 선정에 쓰지 않은 문장에서 이점 소실 |
| 시도별 명시적 시드가 비교 재현성을 높임 | 동일한 설정·입력의 재실행 | 같은 환경에서 파일 또는 측정치가 달라짐. 차이를 기록하고 바이트 재현 보장을 철회 |

초기 회귀 묶음은 Karina와 추가 한국어 화자 2명으로 구성하고, 한 명의 성공을 전체 성능으로 보고하지 않습니다. 서로 다른 말투·높낮이와 깨끗한 단독 발화/배경이 있는 입력을 포함합니다. 동의받은 테스트 녹음이나 출처가 명확한 자료를 우선합니다. 한국어 공개 데이터 후보인 Zeroth-Korean은 CC BY 4.0이며 여러 화자의 전사 음성을 제공하지만, 전체 묶음은 약 10 GB이므로 이번 작업에서 자동 다운로드할 이유는 없습니다. [공식 데이터 안내](https://www.openslr.org/40/).

첫 비교의 상한은 **3명 × 2개 참조 × 2개 문장 × 2개 시드 = 24회 합성**으로 잡을 수 있습니다. 실제 사용자의 신규 프로필 준비에는 먼저 2개 후보 × 2개 시드로 4개 미리 듣기를 만들고, 선택된 후보에서 다른 문장 2회를 확인하는 **최대 6회**의 별도 준비 예산을 권합니다. 일반 메시지 재시도 예산과 혼합하거나 실패할 때마다 새 준비 작업으로 우회하지 않습니다.

문장은 기존 “확인이 필요해요. 잠깐 봐 주세요.”와 미리 듣기 선정에 쓰지 않은 끝말·문장 구조를 조합합니다. 언어 확장 시 숫자·고유명사·마찰음·받침도 별도 사례로 더합니다. 같은 시드는 비교 조건끼리 짝지어 사용하고, 비교 순서는 섞습니다. 가능하면 파일명과 조건을 가린 청취로 자연스러움·발음·배경·참조 유사성을 각각 기록합니다.

통과 기준은 모든 출력의 내용을 보존하고 잘림·토큰 소진을 거부하는 것, 기존 사례에 회귀가 없는 것, 새 화자의 실패율과 모든 실패 파일을 함께 보고하는 것입니다. 자동 수치만 통과한 경우에는 “자동 검사 통과”라고 표시합니다. “고품질 목소리 검증 완료”는 실제 청취 검토와 그 범위를 기록한 경우에 한정해야 합니다.

속도는 다운로드, 모델 로드, 참조 준비, 합성, ASR 검사를 분리해 기록합니다. M1 16 GiB에서는 TTS와 큰 ASR 모델을 동시에 올리는 실험을 피하고, 한 단계·한 모델씩 실행하여 최대 메모리를 측정하는 것이 이 프로젝트의 기존 운영 방식과 맞습니다. [기존 M1 측정과 한계](model-comparison.md).

## 7. 실행 가능한 로컬 대안의 우선순위

기존 [모델 비교 문서](model-comparison.md)의 후보보다 현재 고정된 MLX 배포판에서 확인할 수 있는 경로가 더 늘어 있습니다. 아래 크기는 가중치 파일 크기이며 실행 최대 메모리가 아닙니다. 한국어 청취 우열이나 M1 속도를 이 조사에서 측정하지 않았습니다.

| 후보 | 현재 확인한 실행 경로 | 판단 |
| --- | --- | --- |
| Qwen3-TTS 1.7B Base 4-bit | 현재 제품 경로, 고정 리비전 `37e955a1…` | 참조 준비·재사용 개선의 기준 모델 유지 |
| Qwen3-TTS 0.6B Base | 같은 계열, 기존 M1 비교 기록 있음 | 시간 절감 후보. 모델이 작다는 이유로 한국어 품질을 낮거나 높다고 단정하지 않음 |
| Chatterbox Multilingual V3 | **MLX Audio 0.5.4 안에** 한국어 `ko`와 v3 분기 존재. 주 가중치 약 2.71 GB + 별도 S3Tokenizer 약 0.495 GB | 같은 런타임에서 시도할 첫 대안. 단일 모델 ID뿐 아니라 S3Tokenizer 리비전도 고정해야 함 |
| VoxCPM2 4-bit | 같은 배포판에 2B 모델·한국어·참조 복제·목소리 설계 경로 존재. 주 가중치 약 2.30 GB, 48 kHz 출력 | 다른 구조의 비교 후보. 출력 샘플레이트가 높다는 이유로 자연스러움을 우수하다고 보지 않음 |
| Fun-CosyVoice3 | 공식 한국어·교차 언어 복제 지원. 현재 설치된 MLX 0.5.4 TTS 모듈에는 직접 경로 없음 | 별도 환경·어댑터 검증이 필요하여 이번 재사용 기능보다 후순위 |

Chatterbox의 한국어 비교에는 English/Turbo/Nano 대신 Multilingual 체크포인트를 사용해야 합니다. 현재 MLX 소스는 언어별 분기를 구분하고 영어 전용 체크포인트에 한국어를 전달하면 거부합니다. [고정된 MLX Chatterbox 안내](https://github.com/Blaizzy/mlx-audio/blob/407eb61aec4999ba0c91298095ce7f2ac8c25680/docs/models/tts/chatterbox.md), [언어 처리 구현](https://github.com/Blaizzy/mlx-audio/blob/407eb61aec4999ba0c91298095ce7f2ac8c25680/mlx_audio/tts/models/chatterbox/chatterbox.py#L236-L266).

VoxCPM2 경로는 참조만으로 복제하고, 이어 말하기에는 별도의 `prompt_audio`·`prompt_text`를 받습니다. Qwen의 참조·전사 의미를 모든 모델에 똑같이 전달하는 범용 kwargs 어댑터보다 각 모델의 계약을 분명히 두는 편이 좋습니다. [고정된 MLX VoxCPM2 안내](https://github.com/Blaizzy/mlx-audio/blob/407eb61aec4999ba0c91298095ce7f2ac8c25680/mlx_audio/tts/models/voxcpm2/README.md), [CosyVoice 공식 기능과 설치 경로](https://github.com/QwenAudio/CosyVoice/blob/074ca6dc9e80a2f424f1f74b48bdd7d3fea531cc/README.md).

대안 비교는 먼저 같은 참조와 텍스트로 각 모델의 기본 설정을 확인한 뒤, 모델별로 권장되는 참조 길이·입력 계약을 만족한 조건을 별도 표로 비교해야 합니다. 한 모델이 실패하면 다른 모델이나 유료 API로 자동 전송하지 않습니다. 좋은 참조를 재사용하고 실패 이유를 보존하는 흐름은 특정 모델에 종속시키지 않는 것이 좋습니다.
