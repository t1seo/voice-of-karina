# 자연어로 사용하는 음성 생성 스킬: 아이디에이션

작성일: 2026-09-20

사용 스킬: `brainstorm-ideas-new`. 제품, 디자인, 엔지니어링 관점에서 각각 5개 아이디어를 발산하고, 핵심 가치와 검증 용이성을 기준으로 우선순위를 정리했습니다. 이 문서는 제품 탐색 결과이며, 구현 완료나 모델 성능 측정 결과를 의미하지 않습니다.

## 1. 제품 방향과 확인된 요구

사용자가 Codex 또는 Claude에 YouTube 링크 1~2개와 원하는 문장을 전달하면, 사용할 만한 목소리를 찾아 음성을 만들어 주는 스킬을 제안합니다. 영상이 없으면 목소리 설명으로 새 음성을 만들고, 마음에 든 목소리는 저장해 다시 사용합니다.

- 주 사용자: 코딩 에이전트를 쓰면서 개인 알림음이나 짧은 음성 메시지를 만들고 싶은 사용자입니다.
- 사용자는 CLI 명령, 모델 이름, 전처리 옵션을 직접 고르지 않습니다.
- 로컬 실행을 우선하며, 유료 API도 비교 후보로 포함합니다. 이는 사용자가 확인한 선호입니다.
- 자연스러움, 원하는 화자와의 유사성, 잡음 억제를 각각 평가합니다.
- 음성 생성 속도와 최초 설치·다운로드 시간은 구분합니다.
- 영상 기반 복제, 설명 기반 새 목소리 생성, 저장한 목소리 재사용을 하나의 스킬에서 처리합니다.
- 생성한 파일을 받는 흐름과 실제 알림 설정에 적용하는 흐름을 모두 지원합니다.

현재 작업 컴퓨터에서 확인한 하드웨어는 Apple M1, 통합 메모리 16 GiB입니다. 다른 장치에 배포할 때는 다시 감지해야 합니다.

## 2. 제안하는 사용 경험

### 영상으로 생성

> 이 영상 두 개에서 이 사람이 말하는 목소리로 “작업 끝났어요. 확인해 주세요”를 만들어 주세요. 자연스럽고 차분하게요.

스킬은 이미 전달받은 URL과 문장을 다시 묻지 않습니다. 발화 후보를 찾고, 요청한 문장만 합성해 추천 결과를 제공합니다. 두 영상은 같은 화자의 더 좋은 발화를 찾는 데 사용합니다. 서로 다른 사람의 목소리를 자동으로 섞지는 않습니다.

화자가 명확하지 않은 인터뷰라면 짧은 후보 발화를 들려주고 한 번만 선택받습니다. 화자 분리는 ‘누가 언제 말했는지’를 나누는 기능이며, 영상 속 목소리가 사용자가 지목한 사람인지 알아내는 문제는 별도로 다뤄야 합니다.

### 영상 없이 생성

> 영상 없이, 낮고 차분한 한국어 여성 목소리를 만들어 주세요. 기계적인 안내방송 느낌은 적게 하고, “잠시 쉬어 가셔도 괜찮아요”라고 말해 주세요.

기본 결과를 완성해서 제공하고, 사용자가 비교를 원하면 다른 후보를 추가합니다. 매번 후보 선택을 요구하지 않습니다. 선택한 음색은 기준 음성으로 저장해 이후 문장에도 사용합니다.

### 후속 수정과 재사용

> 방금 목소리를 ‘저녁 알림’으로 저장하고, “오늘도 수고하셨어요”도 만들어 주세요.

> 두 번째 문장만 조금 더 느리게 해 주세요.

저장된 목소리와 수정 대상만 재사용합니다. 원문 변경을 요청받지 않았다면 문장을 임의로 바꾸지 않습니다. 감정·말투 제어는 모델마다 지원 범위가 다르므로, 지원하지 않는 요청을 적용했다고 보고해서는 안 됩니다.

### 적용까지 요청한 경우

> 이 문장을 작업 완료 알림으로 만들어서 바로 적용해 주세요.

요청에 적용 의도가 포함되면 생성 후 해당 도구에 연결하고 결과를 확인합니다. 생성만 요청했을 때는 음성 파일을 결과로 제공합니다. 실패하면 기존 알림음을 유지하고 어느 단계까지 완료했는지 설명합니다.

사용자에게 노출되는 조작은 자연어 스킬 하나입니다. 내부에는 구조화된 요청을 받아 실행하는 엔진이 필요합니다. 기존의 다운로드·합성·설치 기능을 이 엔진으로 재사용하고, 엔진은 진행 상태와 결과 파일을 기계가 읽을 수 있는 형태로 반환하도록 제안합니다.

## 3. 현재 코드에서 확인한 사실과 음질 가설

실제 문제 음원을 청취하거나 재생성한 것은 아닙니다. 아래의 음질 원인은 검증할 가설이며, 코드에서 관찰한 사실과 구분했습니다.

| 관찰한 사실 | 영향 또는 검증할 가설 | 근거 |
|---|---|---|

| 선택한 음성을 정규화하고 16 kHz 모노로 저장해 TTS 참조로도 사용합니다. | 전사용 음성과 합성용 참조를 분리하고, TTS는 모델 입력 규격에 맞춰 변환하는 실험이 필요합니다. 현재 인위적인 음색의 원인이라고 단정할 수는 없습니다. | [generate_samples.py](../src/generate_samples.py), `auto_select_segment` |

| 대화형 파이프라인은 선택에 따라 잡음 제거·EQ·압축·음량 정규화를 함께 적용합니다. | 전처리와 합성 후처리의 영향을 분리해야 합니다. quickstart 생성 경로에는 이 후처리 묶음이 호출되지 않습니다. | [pipeline.py](../src/pipeline.py), `enhance_audio`; [quickstart.py](../src/quickstart.py), `generate` |

핵심 가설은 ‘깨끗한 발화를 먼저 찾고, 필요한 만큼만 처리하면 자연스러움을 더 잘 보존할 수 있다’입니다. 어떤 영상에서도 후처리만으로 원래 음색과 무잡음을 동시에 확보할 수 있다고 약속하지 않습니다.

## 4. 세 관점에서 발산한 15개 아이디어

### 제품 관점: 5개

| ID | 아이디어 | 사용자가 얻는 가치 |
|---|---|---|
| P1 | 링크와 문장을 한 번에 받는 단일 음성 스킬 | 설치 후 정상적인 요청은 추가 설정 질문 없이 결과까지 이어집니다. |
| P2 | 이름을 붙여 저장하는 개인 목소리 보관함 | “어제 목소리로”라는 요청으로 분석을 반복하지 않고 재사용합니다. |
| P3 | 설명으로 만드는 새 목소리 | 적합한 영상이 없어도 원하는 분위기의 음성을 만들 수 있습니다. |
| P4 | 짧은 음성 메시지와 알림 묶음 | 네 가지 고정 이벤트 밖의 임의 문장도 생성하고, 원하면 알림에 연결합니다. |
| P5 | 목적에 맞춘 자동 품질 정책 | 빠른 미리듣기, 음색 유사성, 자연스러움 등 사용자가 말한 우선순위를 실행에 반영합니다. |

| D2 | 결과 중심의 진행 안내 | “깨끗한 발화를 찾고 있어요”, “요청하신 두 문장을 만드는 중입니다”처럼 설명합니다. |
| D3 | 화자가 모호할 때만 짧게 선택 | 두 후보의 실제 발화를 제공하고 원하는 목소리를 한 번 선택받습니다. |
| D4 | 자연어로 특정 결과만 수정 | “두 번째만 천천히”, “이 문장만 바꿔 주세요”를 대상별 재생성으로 연결합니다. |

핵심 문제 해결을 가장 크게 보고, 빠르게 검증할 수 있는지와 이후 차별화로 이어지는지를 함께 고려했습니다.

| 우선순위 | 아이디어 | 선택 이유 | 핵심 가정 | 작은 검증 실험 |
|---|---|---|---|---|
| 1 | 한 번의 자연어 요청으로 끝나는 스킬 (P1·D1·D2) | 사용자가 명시한 UX 목표를 직접 해결합니다. | 필요한 의도를 기존 에이전트가 충분히 구조화할 수 있습니다. | 두 도구에서 링크 1개·2개, 명시 문장·문장 작성 요청 등 10개 대표 요청을 실행해 불필요한 질문과 누락을 기록합니다. |
| 2 | 화자와 음질에 따른 참조 선택·최소 처리 (E1·E2·D3) | 잡음과 인위적인 음색 모두 입력 단계에 원인이 있을 수 있습니다. | 좋은 원본 구간을 고르는 것이 일괄 분리보다 유리한 경우가 많습니다. | 같은 화자·같은 문장으로 구간 선택과 처리 강도를 분리한 비교 청취를 합니다. |
| 3 | 설명 기반 새 목소리와 저장 (P3·E4) | 영상 없이 생성하려는 요구를 충족하고 입력 음원 품질 문제를 피할 수 있습니다. | 자연어 설명으로 만든 음색이 사용자 기대에 충분히 맞습니다. | 세 가지 한국어 음색 설명으로 생성하고, 저장한 음색이 다른 문장에서도 유지되는지 비교합니다. |
| 4 | 보이스 프로필·참조 캐시·Mac 실행 개선 (P2·E3) | 반복 요청의 대기 시간과 목소리 변화를 줄입니다. | 실제 사용에서 같은 목소리를 여러 번 쓰는 비중이 큽니다. | 첫 등록과 이후 한 문장 추가를 나눠 시간·메모리·재사용 단계를 측정합니다. |
| 5 | 결과별 수정과 품질 검사 (D4·D5·E5) | 실패를 다시 처음부터 시작하지 않고 해결합니다. | 자동 검사가 청취상 불량 후보를 유용하게 걸러냅니다. | 오류 사례를 모아 검사의 누락·오탐을 확인하고, 수정한 문장 이외의 파일이 유지되는지 검증합니다. |

## 6. 음질 개선의 구체적인 탐색 방향

### 참조 음성 준비

1. 원본을 보존하고 음성 활동이 있는 구간을 찾습니다.
2. 겹쳐 말하기·음악·클리핑이 많은 구간을 우선 제외합니다.
3. 두 영상이면 같은 화자의 후보를 비교합니다. 백엔드가 복수 참조를 지원하지 않으면 가장 적합한 단일 참조를 선택합니다.
4. 먼저 원본 발화로 짧게 합성합니다. 문제가 있는 후보에만 약한 잡음 제거 또는 음악 분리를 적용해 비교합니다.
5. ASR용 변환 음성과 TTS용 참조를 분리합니다. 합성용 참조는 모델별 입력 규격에 맞춥니다.
6. 전사는 선택한 구간에 대해 수행하고, 텍스트와 음성 구간이 정확히 대응하도록 저장합니다.

‘두 링크를 넣으면 둘을 이어 붙인다’는 규칙은 피합니다. 녹음 환경이 다른 구간을 연결하면 참조가 불안정해질 수 있다는 가설을 검증해야 합니다. 복수 참조 지원과 텍스트 정합 방식도 백엔드별로 다릅니다.

### 합성 이후

- 기본 후보는 과도한 잡음 제거·EQ·압축 없이 생성합니다.
- 필요할 때 끝부분 정리와 적절한 음량 조절을 적용합니다. 참조 전처리와 출력 후처리의 효과를 따로 평가합니다.
- ASR로 요청 문장과 결과를 비교하되, 한국어 띄어쓰기·숫자 표기를 정규화합니다. ASR 오류를 곧바로 TTS 오류로 단정하지 않습니다.
- 짧은 알림음에서는 자음·받침, 끝음 잘림, 반복, 금속성 잔여음, 갑작스러운 볼륨 변화를 중점적으로 듣습니다.
- 자동 품질 점수는 후보를 줄이는 보조 수단입니다. 사람에게 자연스럽고 원하는 사람처럼 들리는지는 비교 청취로 판단합니다.
- 재시도 예산을 둡니다. 예를 들어 최초 생성 후 두 번까지만 개선 후보를 만들고, 품질이 부족하면 더 좋은 구간 또는 다른 영상을 요청합니다. 이는 제안한 정책이며 현재 구현이 아닙니다.

## 7. 모델과 실행 방식 후보

아래는 공식 저장소·개발자 문서·배포 모델 카드에서 확인한 기능입니다. 현재 프로젝트의 한국어 알림음이나 M1에서 어느 모델이 더 좋은지는 아직 측정하지 않았습니다.

| 후보 | 확인한 기능 | 이번 제품에서의 역할과 검증점 |
|---|---|---|
| Qwen3-TTS Base + MLX | 현재 모델 계열의 복제 기능을 MLX로 사용할 수 있습니다. 0.6B 4-bit와 1.7B 8-bit 배포본이 있습니다. [MLX 문서](https://github.com/Blaizzy/mlx-audio/blob/main/docs/models/tts/qwen3-tts.md), [0.6B 카드](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-0.6B-Base-4bit), [1.7B 카드](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-1.7B-Base-8bit) | Mac에서 먼저 비교할 실행 후보입니다. 0.6B는 빠른 생성 후보, 1.7B는 품질 후보로 비교하되 실제 우열은 측정합니다. 양자화가 한국어·음색에 미치는 영향도 확인합니다. |
| Qwen3-TTS VoiceDesign / CustomVoice | VoiceDesign은 설명 기반 생성, CustomVoice는 준비된 음색 기반 생성입니다. 한국어를 지원하며 한국어 프리셋도 있습니다. [Qwen 공식 문서](https://github.com/QwenLM/Qwen3-TTS) | ‘영상 없이 생성’을 가장 직접적으로 추가할 후보입니다. 현재 Base 체크포인트와는 다른 모델입니다. |
| Chatterbox Multilingual V3 | 0.5B 다국어 모델이며 한국어를 지원합니다. Turbo·Nano는 영어 모델로 구분됩니다. [공식 저장소](https://github.com/resemble-ai/chatterbox) | 다른 계열의 복제 품질 비교 후보입니다. 한국어에는 Multilingual을 평가해야 하며, Mac에서의 실행성·지연도 확인해야 합니다. |
| Fun-CosyVoice3 0.5B | 한국어를 포함한 다국어 zero-shot 복제를 지원합니다. [공식 모델 카드](https://huggingface.co/FunAudioLLM/Fun-CosyVoice3-0.5B-2512) | 짧은 한국어 문장의 발음과 운율 비교 후보입니다. 현재 Mac 환경의 설치·추론 경로는 추가 검증이 필요합니다. |
| Fish Audio S2 Pro | 한국어, 음성 복제와 세밀한 표현 제어를 제공합니다. 4B 계열이며 모델 카드에는 비상업·연구용 이용과 상업용 별도 라이선스 조건이 명시됩니다. [공식 저장소](https://github.com/fishaudio/fish-speech), [모델 카드](https://huggingface.co/fishaudio/s2-pro) | 품질 비교 후보입니다. M1·16 GiB에서의 메모리와 처리 속도를 먼저 검증해야 하며, 기본 엔진으로 바로 선정하지 않습니다. |
| ElevenLabs API | 복제, 준비된 음성, 설명 기반 Voice Design을 제공합니다. [공식 문서](https://elevenlabs.io/docs/overview/capabilities/voices) | 로컬 결과와 비교할 선택적 API 후보입니다. 계정·비용·음성 등록 조건을 확인한 뒤 사용자가 선택할 때 사용합니다. |

추천하는 첫 비교 조합은 현재 Qwen 경로, Qwen MLX 경로, 그리고 Chatterbox Multilingual V3 또는 CosyVoice3 중 실행 가능한 한 후보입니다. 처음부터 모든 모델을 제품에 통합하지 않아도 핵심 가설을 검증할 수 있습니다.

설명 기반 목소리는 첫 생성 음성을 기준으로 저장하고 재사용하는 방식을 권합니다. Qwen은 VoiceDesign으로 만든 음성을 Base의 참조로 사용하는 공식 예제를 제공합니다. 매번 설명만으로 새로운 음색을 뽑는 경우와 일관성을 비교할 수 있습니다. [Qwen의 Voice Design then Clone](https://github.com/QwenLM/Qwen3-TTS#voice-design-then-clone)

## 8. 성능 개선 아이디어

| 개선 | 기대 효과 | 확인할 점 |
|---|---|---|
| 요청한 문장만 생성 | 기본 알림 6개를 불필요하게 만드는 일을 줄입니다. | 문장 목록이 정확히 일치하는지 확인합니다. |
| 원본 후보 선별 후 필요한 구간만 분리 | 전체 영상에 무조건 분리 모델을 적용하는 비용을 줄일 수 있습니다. | 분리 전후 경계와 문장 완결성을 확인합니다. |
| 보이스 프로필에 참조·전사·모델별 특징 저장 | 반복 요청에서 다운로드·분리·전사·특징 추출을 재사용합니다. | 모델·입력 변경 시 캐시가 올바르게 무효화되는지 확인합니다. |
| 같은 요청 안에서 모델 한 번 로드 | 여러 문장을 만들 때 초기화 비용을 공유합니다. | 현재도 생성 루프 안에서는 한 번 로드합니다. 추가 개선은 참조 특징 재사용과 요청 간 유지의 효과를 구분해야 합니다. |
| 장치에 맞는 MLX·양자화 후보 비교 | Mac의 시간·메모리 개선 가능성을 검증합니다. | 다른 장치의 공개 벤치마크 수치를 이 M1의 결과로 사용하지 않습니다. |
| 단계별 모델 해제와 작은 배치 | ASR·분리·TTS 모델의 동시 메모리 점유를 줄입니다. | 상주 모델 캐시는 16 GiB 메모리 여유와 실제 재사용 빈도가 확인된 경우에 선택합니다. |
| 실패한 문장만 재생성 | 짧은 수정의 대기 시간을 줄입니다. | 같은 음색과 나머지 결과가 유지되는지 확인합니다. |

Qwen 공식 구현에는 `create_voice_clone_prompt`로 참조 특징을 한 번 준비해 여러 합성에 재사용하는 경로가 있습니다. MLX 등 다른 어댑터는 동일한 기능과 저장 형식이 지원되는지 따로 확인해야 합니다. [공식 참조 재사용 예제](https://github.com/QwenLM/Qwen3-TTS#voice-clone)

캐시는 URL만으로 식별하지 않습니다. 영상 ID·원본 지문·선택 구간·화자·처리 설정·전사·모델 버전으로 참조를 식별하고, 최종 음성은 여기에 문장·생성 설정을 포함합니다. 새 목소리도 설명뿐 아니라 선택한 기준 음성을 저장합니다.

API는 자동 대체 경로로 두지 않는 것을 제안합니다. 로컬 실행 선호를 유지하면서, 사용자가 API 사용과 비용 범위를 선택한 작업에만 적용합니다.

## 9. 작은 실험부터 판단하는 방법

### 실험 A: 구간 선택이 문제인지 확인

- 한 사람만 말하는 영상과 잡음·진행자가 있는 영상에서 현재 음량 기반 선택과 제안하는 발화 기반 선택을 비교합니다.
- 같은 모델, 동일 처리, 같은 한국어 문장 3개를 사용합니다.
- 목표 화자 선택 정확성, 자연스러움, 유사성, 잡음을 각각 기록합니다.
- 화자 정답은 청취로 확인합니다. 화자 유사도 점수 하나로 정체를 확정하지 않습니다.

### 실험 B: 처리 강도가 문제인지 확인

- 참조 구간을 고정하고 원본, 약한 잡음 제거, Demucs 분리의 세 조건을 비교합니다.
- 깨끗한 구간과 잡음 구간 각각에서 3문장을 생성하면 18개 결과로 1차 비교할 수 있습니다.
- 합성 후처리를 끈 상태에서 먼저 비교하고, 이후 같은 합성 결과에 후처리를 적용해 영향을 분리합니다.
- 청취 비교는 모델·처리 이름을 가리고 순서를 섞으며, 음량 차이가 선택을 지배하지 않도록 맞춥니다.

### 실험 C: 모델과 실행 속도 비교

- A·B에서 선택한 참조와 동일 문장으로 후보 모델을 비교합니다. 백엔드별 필수 입력 차이는 기록합니다.
- 최초 준비 시간, 모델이 없는 상태의 다운로드 시간, 로드 시간, 첫 재생 가능한 결과까지의 시간, 전체 완료 시간, 최대 메모리를 분리합니다.
- 같은 목소리의 두 번째 요청에서 어느 단계가 생략됐는지 기록합니다.
- 한국어 문자 오류율, 반복·누락·끝음 잘림과 사람의 자연스러움·음색 유사성 평가를 함께 봅니다.
- 모델 크기나 마케팅 수치로 우열을 결정하지 않습니다. 개선 배수나 완료 시간은 실제 측정 후 제시합니다.

### 실험 D: 새 목소리와 스킬 경험

- 서로 다른 음색 설명 3개로 새 목소리를 만들고, 각 기준 음성으로 다른 문장 3개를 생성합니다.
- 설명 충족도와 문장 간 목소리 일관성을 확인합니다. 특정 인물과의 유사성은 새 목소리의 평가 목표가 아닙니다.
- Codex와 Claude에서 같은 대표 요청을 실행하고, 추가 질문 수와 수정 성공률을 비교합니다.
- 정상 입력은 기술 설정 질문 없이 완료하는 것을 목표로 합니다. 화자가 모호한 경우의 선택과 최초 환경 준비는 별도로 기록합니다.

첫 개발 범위로는 단일 스킬, 요청 문장만 생성, 참조 선택 개선, 새 목소리 생성, 보이스 프로필을 권합니다. 모델 최종 선정과 기본 처리 강도는 위 비교 결과로 결정하는 편이 타당합니다.

## 10. 이번 탐색의 범위

- 프로젝트 코드와 관련 스킬 문서를 읽고 공식 모델 자료를 조사했습니다.
- 이 문서만 추가했습니다. 기존 코드·환경·알림 설정은 변경하지 않았습니다.
- 모델 설치, 음성 생성, 청취 비교, 속도 벤치마크는 수행하지 않았습니다.
- 따라서 음질 원인, 최적 모델, M1에서의 성능 개선 폭은 아직 확정하지 않았습니다.
